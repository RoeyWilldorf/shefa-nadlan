# שפע נדל״ן — הפעלה ומסירה

הפרויקט כולל אתר בעברית וממשק משרד תחת `/office`. גרסת הבדיקה נשמרת בנפרד מהגרסה המוגשת באתר. ההרשאות של Sites ומזהה הפרויקט מוגדרים מחוץ לקוד היישום. יש לעבוד עם אותו פרויקט ולהשאיר את הגישה לבעלי האתר לפי ההגדרה הקיימת.

## הפעלה מקומית

```sh
npm ci
npm test
npm run build
npm run dev
```

נדרש Node.js 22.13 ומעלה. סביבת הפיתוח יוצרת SQLite מקומי ומדמה את אחסון הקבצים עם תיקייה מקומית. יש להשתמש בה בנתונים סינתטיים בלבד. כתובת ההפעלה מודפסת במסוף. קבצי ההסבה נמצאים ב־`drizzle/` ורצים לפי סדר ה־journal. `dist/` כולל את נכסי האתר, ו־`dist/server/index.js` נבנה אוטומטית מ־`worker/`.

## עבודה משרדית

1. פותחים נכס כטיוטה, מזינים מידע מאומת, מקצים מתווך ומצרפים תמונות שאושרו לשימוש. מפרסמים בקטלוג רק אחרי אישור מפורש. תיקון מחיר כולל מקור או סיבת שינוי.
2. פניות חוזרות מחוברות לכרטיס קיים לפי פרטי זיהוי מנורמלים. בכרטיס הליד ניתן לבדוק את השיוך, לתעד שיחות וליצור משימות וסיורים. בקשה מהאתר מציעה מועד ומספר נכסים. המשרד מאשר מועד מול הלקוח.
3. בכרטיס העסקה יוצרים עסקה ומשייכים נכס וליד. מתעדים עמלה מוסכמת, תקבולים, הוצאות וחלוקה. עדכון עמלה וחלוקה מחייב תיעוד אישור. הסטטוסים והסכומים שמורים בכרטיס העסקה.
4. בכרטיס נכס אפשר להפיק טיוטת PDF ממותגת לבעלים, ובמסלול בלעדיות גם טיוטות נפרדות לבלעדיות ולפעולות השיווק. עותק חתום שנוצר במסלול הבדיקה לקונה או שוכר ניתן להורדה דרך כרטיס הליד. החתימה במערכת סגורה בהגדרת ברירת המחדל. אין להזין בתצוגת הבדיקה תעודות זהות או חתימות אמיתיות.
5. קישורי WhatsApp מפנים לפתיחת שיחה לפי בחירת המשתמש. טיוטות השיווק והמודיעין מאפשרות עבודה ידנית עם מקורות מורשים. משלוח דוא״ל אוטומטי ושידור לרשתות דורשים חיבור ייעודי.

## טיפול בדיווח נגישות

טופס הדיווח בהצהרת הנגישות פותח פנייה ומשימת טיפול אחת ב־CRM עם מספר פנייה משותף. באזור ״משימות וסיורים״ פותחים ״בדיקת דיווח נגישות״, מאשרים אחראי ומוסיפים מועד לבדיקה חוזרת. בהערות מתעדים מה התקבל, חלופת שירות שנמסרה, תיאור תיקון ותוצאת בדיקה חוזרת. סוגרים את המשימה לאחר אימות. ביומן הבקרה נרשמים פתיחת הדיווח ועדכון המשימה.

לפני פתיחה לציבור יש לאמת את פרטי הקשר והסדרי הנגישות במשרד, לבדוק אם נדרש רכז, להשלים בדיקת קוראי מסך במכשירים אמיתיים ולוודא שהמסמכים עוברים בדיקת קריאה וסדר תקינה. ליקוי מהותי במסלול הלקוח חוסם השקה עד תיקון ובדיקה חוזרת. תכונות חדשות כמו מפה, אזורים אישיים וצ׳אט מחייבות בדיקות עצמאיות לפני הפעלה.

## גיבויים ושחזור

בעל האתר יכול להוריד גיבוי JSON מלא של טבלאות המסד דרך המשרד או `GET /api/office/backup`. הגיבוי כולל מידע פרטי ויש לשמור אותו בהצפנה ובגישה מוגבלת. יש לגבות בנפרד את קובצי האחסון ואת גרסאות מפתחות ההצפנה ולשמור אותם בנפרד מן הגיבוי. הגיבוי של המסד כולל הפניות לקבצים.

```sh
node scripts/restore-office.mjs /path/to/snapshot.json /path/to/new-backup.sqlite
```

הסקריפט משחזר למסד חדש ומבצע בדיקות שלמות ומפתחות זרים. עובדים תמיד על מסד חדש. לפני פריסה יש לייצא את מסד הייצור, לשחזר עותק נפרד, לבדוק ספירות, לדגום נכסים ותיקים ומסמכים, ולבדוק פתיחת הקבצים מול עותק האחסון. חזרה לגרסת קוד קודמת ושחזור מסד נבחנים בנפרד. ההסבה הנוכחית מוסיפה טבלאות.

## הגדרות והעברה לספק אחר

השרת מקבל מסד D1 ב־`DB`, אחסון תואם R2 ב־`BUCKET`, כתובת בעל החשבון ב־`OFFICE_OWNER_EMAIL` ומפתח חתימות ב־`VISIT_ENCRYPTION_KEY`. כתובת הבעלים משמשת להרשאת ניהול. `BROKERAGE_SIGNING_APPROVED` צריך להישאר חסר עד אישור עורך דין, סיום בדיקות והתאמת החתימות. אין להעביר ערכי סודות בקוד או בגיבוי Git. כתובת השליחה הרשמית היא הגדרה עסקית נפרדת שתידרש בחיבור הדוא״ל.

למעבר לספק אחר יש להעביר את מקור Git, ייצוא SQLite וקובצי האחסון עם המפתחות שלהם, להכין מתאמים ל־DB ולאחסון אם הממשקים שונים, ולהחליף זיהוי משתמשי Sites במנגנון הרשאה מקביל לאחר בדיקות גישה. לפני החלפת דומיין יש לבדוק התאמה של מזהים, מדיה, קישורי נכסים ומסמכים ונתיבי גישה פרטיים. אישור פריסה לייצור ניתן בידי רועי או שרל לאחר קבלת דו״ח הבדיקות.
